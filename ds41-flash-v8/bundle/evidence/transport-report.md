# 跨框架 PD 修复与压测结果

测试日期：2026-09-20（Asia/Singapore）。P 为双 RTX 6000D、vLLM TP2/P21；D 为四台 Spark、SGLang TP4/D40。

## 结果

**正确性门禁 7/7 通过，压测 24/24 场景、172/172 请求通过，失败 0。每条压测请求实际输出 256 tokens。**

门禁包含中文问答、计算、照抄和 4931-token 长文口令检索。矩阵为每档一次并发突发请求，输入为重复代码资料及中文解释任务；不是长期稳态压测或通用模型准确率评测。

## 配置与统计口径

- 输入为精确的 8192、32768、65536、100000 tokens，实际 usage 已逐条校验。聊天模板仅一套。
- 并发为 1、2、4、8、12、16。D 最大运行请求 12，因此 C16 包含排队，不能当成 16 条同时解码。
- 投机解码关闭；D 上下文上限 300000、KV 池上限 2000000 tokens、静态内存比例 0.95。
- 每请求独立 cache salt，避免不兼容的前缀复用；结果包含实际 prefill、搬运、尾部重算及排队。

## 两项故障的修复

1. 搬运失败的主要原因是页地址重复乘以页大小，导致访问越界；现按每页字节跨度计算，并保留所有 producer 缓存组、校验地址边界与 engine ID、按本地 agent 注册远端内存。完成后通知两个 P rank 释放缓存。
2. KV 按 payload/scale 分区搬运，正确处理 P 的 64 条目块、D 的 128/256 条目页及裁剪后的 SWA。Indexer 从 P 的 FP8 转为 D 的 MXFP4；偶数边界恢复压缩状态，并由完整 D 模型重算尾部后采样。
3. 健康探针绕过跨引擎尾部逻辑；移除向 ZMQ 端口错误发送 HTTP 的旧心跳。

4. 代理每次使用新的 HTTP 连接，避免复用 D 已关闭的空闲连接而丢失请求；不自动重放可能已被引擎接受的推理 POST。
